# Redis

![redis](../using_files/img/system/redis.png)

## 核心概念

1. Key-Value 存储

   ```Text
   Redis 是一个基于内存的键值数据库。
   支持多种数据类型，不仅限于字符串，还包括列表、集合、有序集合、哈希表等。
   所有数据都保存在内存中，保证极高的读写速度。
   ```

2. 数据结构类型

   ```Text
   - String：最基本的数据类型，可存储文本、数字或二进制数据。
   - List：有序链表结构，可实现队列或消息队列功能。
   - Set：无序集合，元素唯一，可做集合运算（交、并、差）。
   - Hash：键值对集合，常用于存储对象属性。
   - ZSet（Sorted Set）：带分数的有序集合，用于排行榜或权重排序。
   - Stream：日志流数据结构，可用于事件流或消息系统。
   ```

3. 单线程模型

   ```Text
   Redis 采用单线程事件循环机制（基于 epoll）。
   通过 I/O 多路复用实现高并发。
   优势：避免多线程锁竞争问题，性能稳定。
   ```

4. 持久化机制

   ```Text
   Redis 虽然是内存数据库，但提供持久化选项：
   - RDB（快照）：定时保存数据的二进制快照文件。
   - AOF（Append Only File）：记录每次写操作，可重放恢复数据。
   - 混合模式（RDB + AOF）：兼顾性能与安全。
   ```

5. 发布订阅（Pub/Sub）

   ```Text
   一种消息传递机制：
   客户端可以订阅频道（Channel），其他客户端向该频道发布消息时，订阅者会立即收到。
   ```

## 高可用与分布式

1. 主从复制（Replication）

   ```Text
   一主多从架构。
   主节点写，从节点只读。
   可实现读写分离与数据备份。
   ```

2. Sentinel（哨兵）

   ```Text
   监控主节点健康状态。
   当主节点宕机时，自动将从节点提升为主节点。
   提供高可用性（HA）。
   ```

3. Cluster（集群）

   ```Text
   实现数据分片（Sharding）和水平扩展。
   每个节点保存一部分数据槽（slot），自动均衡负载。
   集群内部通过 Gossip 协议保持通信。
   ```

## 常见应用场景

1. 缓存系统

   ```Text
   减轻数据库压力，提升响应速度。
   常与过期时间（EXPIRE）和淘汰策略（LRU、LFU）配合使用。
   ```
2. 分布式锁

   ```Text
   使用 SETNX + EXPIRE 实现。
   确保同一资源在分布式环境下只被一个客户端操作。
   ```
3. 消息队列

   ```Text
   使用 List 或 Stream 实现。
   Stream 支持消费者组（Consumer Group），适合高可靠消息传递。
   ```
4. 排行榜 / 计数器

   ```Text
   使用 ZSet 可实现实时排行榜。
   INCR / DECR 可实现高效计数功能。
   ```
5. 会话管理

   ```Text
   存储用户登录状态或临时会话数据。
   通常与 Web 应用结合使用。
   ```

## 运维与优化

1. 性能优化

   ```Text
   - 合理设置过期时间，避免内存爆炸。
   - 使用 Pipeline 批量操作减少网络开销。
   - 开启压缩或持久化策略时，需平衡性能与安全。
   ```

2. 安全机制

   ```Text
   - 设置 requirepass 密码。
   - 限制外部访问，仅允许特定 IP。
   - 结合防火墙和 SSL 加密传输。
   ```

3. 监控与可视化

   ```Text
   可使用 Redis-CLI、RedisInsight、Prometheus 等工具监控性能与命令执行。
   ```
